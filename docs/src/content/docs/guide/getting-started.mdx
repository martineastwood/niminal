niminal is in **alpha**. Syntax and behaviour can change; expect rough edges.

## Install

### On a Mac (Apple Silicon, macOS 13+)

Download the dmg from [GitHub Releases](https://github.com/martineastwood/niminal/releases) and drag the **Niminal** folder onto Applications. It holds Stage, the VS Code extension and the examples. Stage has the audio engine inside it, so there is nothing else to start.

Or with Homebrew:

```sh
brew tap martineastwood/niminal
brew trust --cask martineastwood/niminal/niminal   # recent Homebrew only
brew install --cask martineastwood/niminal/niminal
```

The app is not notarized by Apple. If you used the dmg and macOS blocks it, approve it under **System Settings > Privacy & Security > Open Anyway**. Homebrew clears that warning for you.

### From source

You need a recent [Rust toolchain](https://rustup.rs/), and Node.js and the [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) to build Stage (see [stage/](https://github.com/martineastwood/niminal/tree/main/stage)). For the command-line tools, from a clone of the [repo](https://github.com/martineastwood/niminal):

```sh
cargo install --path crates/niminal-cli    # niminal: play, render, server, replay and the language server
```

Check them:

```sh
niminal --version
```

## Hear something

Save this as `saw_lead.nml` (or use `examples/saw_lead.nml` in the repo):

<Example file="saw_lead.nml" />

Render it to a WAV file with `niminal`, or open it in Stage and evaluate it:

```sh
niminal render saw_lead.nml --out saw_lead.wav
```

Open the `.nml` file: tempo, an instrument with units (`hz`, `db`, `ms`), an envelope, and notes timed with `at`.

More examples live under `examples/` — kits and grids (`drums.nml`, `breakbeat.nml`), scenes (`groove.nml`), buses (`room.nml`), and arrangements (`song.nml`).

## Live coding in an editor

The [VS Code / Cursor extension](/reference/editor/) brings live coding to your own editor: highlighting, diagnostics while you type, and evaluate-while-playing. [Stage](/reference/stage/) does the same in a window of its own, with scenes, lanes and meters beside the code.

With the macOS download, choose **File > Install VS Code Extension…** in Stage (it also offers it the first time it opens). Otherwise, from a clone of the repo:

```sh
cd editors/vscode && npm install && node install.js   # --cursor for Cursor
```

Reload the window and open a `.nml` file and press **Cmd+Enter** (macOS) or **Ctrl+Enter** to evaluate the block around the cursor. The status bar shows the bar and tempo, and the sidebar lists scenes and clips. The extension starts the audio server if none is running, and it stops when the last client closes. The language server (`niminal lsp`) works without a server for hover, completion, and errors.

## Live coding in Stage

Open Niminal Stage, open a `.nml` file (try `examples/groove.nml`) and press **Cmd+Enter** to evaluate a block. The engine is inside Stage and plays through your default sound card (choose another under **Audio**), so there is nothing to start first. See [Live coding](/guide/live-coding/) for quantization, MIDI, and session replay.

## If something goes wrong

niminal keeps its logs in `~/.niminal/`:

| File | What it holds |
| --- | --- |
| `crash.log` | A panic in `niminal` or Stage, with the version and a backtrace |
| `sessions/` | A log of each session, newest kept |

If you report a problem, [open an issue](https://github.com/martineastwood/niminal/issues/new?template=bug_report.md) with the version from `niminal --version`, a minimal `.nml` file that shows it, and any of these files.
