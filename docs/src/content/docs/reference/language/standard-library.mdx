**Compiled by niminal.** These modules are ordinary source, compiled by the server — and offered as presets in the tracker.

The modules under `std/` come with niminal. They are ordinary niminal source, read from the program itself, so `use std/filters` works anywhere and nothing needs installing. They are also the best examples of what [functions](/reference/language/functions/) can do, so read them: they are short.

```nml
instr pad(freq: hz) {
  out = osc(saw, freq).ladder(cutoff: 900hz, res: 0.4)
  out += out.fdn_reverb(time: 2.5sec) * 0.3
}
```

A function from a module is called like any other, as a method or with the signal first. Parameters marked `init` are read when a note starts. The ratios and other tables the functions use are public too (`drum_modes`, `fdn_lengths`, and so on), so you can use them or write your own.

## Building blocks that are opcodes

The filters, resonators and reverbs everything else is made of run natively and need no `use`; the [opcode list](/reference/opcodes/) has each one.

| Opcode | What it is |
| --- | --- |
| `ladder(x, cutoff, res: 0.3, drive: 1)` | A four-pole low-pass with a `tanh` in each stage, like a transistor ladder. `res` near 1 rings and then sings at the cutoff. Loud input, or a higher `drive`, saturates the stages, as it should. |
| `biquad_lp`, `biquad_hp`, `biquad_bp`, `biquad_notch`, `biquad_allpass` `(x, cutoff, q)` | Two-pole sections. `q` is the height of the peak at the cutoff; 0.707 is flat. |
| `biquad(x, b0, b1, b2, a1, a2)` | One biquad section from its coefficients, for building your own. |
| `modal(x, freq, ratios, decay: 300ms)` | A resonator for each of `ratios` times `freq`, in parallel: bars, bells and drums. |
| `delay(x, time, feedback, damp)` | A delay line; `damp` darkens each echo, like a tape delay. |
| `fdn_reverb(x, time, damp, size)` | A feedback delay network of eight lines. |

## std/filters

| Function | What it is |
| --- | --- |
| `onepole_lp(x, cutoff)`, `onepole_hp(x, cutoff)` | One pole: 6db an octave. |

## std/physical

| Function | What it is |
| --- | --- |
| `string(x, freq: init hz, decay: 0.996, damp: 0.5, max: 50ms)` | A plucked string (Karplus-Strong): `comb` with the delay tuned to the pitch. Feed it a short, bipolar burst such as `noise() * env[1 4ms 0]`; a click with only positive values gives a string that only drifts. `decay` near 1 rings longer, `damp` is how fast the highs die away, and `max` is the longest period (the lowest `freq` is 1 / `max`). |
| `membrane(x, freq: init hz, decay: 150ms)` | The first eight modes of a circular membrane. |
| `free_bar(x, freq: init hz, decay: 500ms)` | A free bar, as in a glockenspiel. |
| `bell(x, freq: init hz, decay: 750ms)` | A bell, with a hum an octave below the strike note. |

These are `modal` with a set of ratios; `modal` is an opcode.

```nml
use std/physical
instr tom(freq: hz = 110hz) { (impulse(1hz) * 0.5).membrane(freq) }
```

## std/delays

For echoes at times of your own, add `delay`s: `x + x.delay(120ms) * 0.6 + x.delay(250ms) * 0.3`. Each is its own delay line, so each tap can have its own time, be modulated (`x.delay(250ms + lfo(0.3hz) * 5ms, max: 300ms)`), be filtered or be panned.

| Function | What it is |
| --- | --- |
| `echoes(x, count: 4, spacing: 120ms, fade: 0.6)` | `x` followed by `count` echoes, `spacing` apart, each `fade` times the level of the one before. |
| `tape(x, time, feedback: 0.5, damp: 4khz, max: 2sec)` | `x` plus a feedback delay with a low-pass in the loop, so each repeat is darker. |

## std/spectral

These use [`frames`](/reference/language/functions/#frames-and-the-fft), so each is `size` samples late (1024 unless you give `size`); the compiler delays the path beside it to match.

| Function | What it is |
| --- | --- |
| `band_keep(x, lo: 0, hi: 0.25, size: 1024)` | Keeps the part of the spectrum from `lo` to `hi`, as fractions of the way to half the sample rate. |
| `robot(x, size: 1024)` | Keeps every magnitude and zeroes every phase: a buzz at the frame rate. |
| `blur(x, amount: 0.9, size: 1024)` | Mixes each spectrum with the ones before it: a long wash. |
| `denoise(x, threshold: 0.01, size: 1024)` | Silences the bins quieter than `threshold`: a spectral noise gate. |

## std/instruments

Finished instruments with a few controls each, for when you want a sound and not a function. `use std/instruments.{kick, bass}`, then play them by name (`instrument: kick`, or `kick(freq: c2) for 1beat`). Each is complete on its own, so you can copy one into your file and change it. The tracker offers the same list under **▾** beside **+** in its instruments. `std/instruments`, `std/drums` and `std/fx` are *shelves*: you name what you take, and only that is added. `niminal presets` lists everything on them with a description (`--kind fx` narrows it), `niminal presets kick_808` prints one to paste and change, and the editor completes the names inside `use std/drums.{`. Type the start of any preset name elsewhere in a file and the editor offers it twice: the name, which adds it to your `use` lines, and `(copy source)`, which pastes its definition (with the functions it needs) for you to change. The tracker's preset browser shows the same list. A comment line `// folder: drums/kicks` between definitions files the ones after it under that folder.

| Instrument | What it is |
| --- | --- |
| `kick(freq: 55hz, punch, decay)` | A sine that drops in pitch, with a click on the front. |
| `snare(freq: 180hz, snap, decay)` | A short triangle thump under band-passed noise. |
| `hat(open)` | High-passed, crushed noise; `open` goes from a tick to a wash. The note's pitch is ignored. |
| `bass(freq, cutoff: 600hz, res)` | A saw with a sine an octave down, through a low-pass. |
| `pluck(freq, tone, decay)` | A plucked string that is bright at the start and dulls as it dies away. |
| `pad(freq, attack, release, detune)` | Three slightly detuned saws, softened by a low-pass, with a slow envelope. |
| `lead(freq, cutoff: 2500hz, vibrato)` | A saw with vibrato, through a low-pass. |
| `bell(freq, decay)` | A struck bell from two sines, one bending the phase of the other. |

## std/drums

A drum machine voice and twenty-one presets of it. `drum` is a function with the controls of a drum voice: an oscillator (`wave` sine, tri, square or saw; `freq`, `attack`, `decay`) with a pitch modulation (`mod_mode` `drop`, `wobble` or `random`; `mod_amount` in semitones, `mod_rate`), a noise source with its own filter (`noise_filter` low, band or high; `noise_freq`, `noise_q`) and envelope (`noise_shape` `soft`, `linear` or `burst`; `noise_attack`, `noise_decay`), a `mix` between the two, `drive`, one EQ band (`eq_freq`, `eq_gain`) and `amp`, and a velocity: `vel` (how hard the note is played) with `osc_vel`, `noise_vel` and `mod_vel` saying how much it changes the oscillator, the noise and the pitch modulation. The choices shape the instrument and are fixed when it is compiled; the numbers stay live. The output is soft-clipped, so every setting is bounded.

`use std/drums.{kick_808, snare_tri}`, then play a preset by name, or call `drum(...)` inside an instrument of your own. Each preset takes the note as a tuning (`c3` plays it as designed), takes the note's `gain` as its velocity, and exposes the same numeric controls, so any lane can reshape any sound. The hats share a choke group, so a closed hat ends an open one.

| Presets | |
| --- | --- |
| `kick_deep`, `kick_808`, `kick_punch`, `kick_click`, `kick_dirty` | Kicks from a long sub to a hard, driven one. |
| `snare_tri`, `snare_tight`, `snare_fat` | Snares with a triangle body and band-passed noise. |
| `clap`, `clap_room` | Noise chopped into bursts, dry and with a long tail. |
| `hat_closed`, `hat_open`, `hat_tick` | Hi-hats from high-passed noise. |
| `tom` | A tom; play different notes for a set. |
| `rim`, `cowbell` | Square-wave percussion: a rim shot and a driven cowbell. |
| `zap`, `blip`, `wobble_bass`, `sweep`, `crash` | Effects: a laser, random-pitch bubbles, a slow wobble, a rising noise band, a cymbal. |

Keep a preset's name different from the choice words above (a preset called `wobble` would quietly stop a file playing), and from the instruments in `std/instruments`. The tracker lists these under **▾** beside **+** in its instruments; adding one copies the `drum` function into the project with it, so the copy stands alone.

## std/fx

`std/fx` is a shelf, not a module to take whole: `use std/fx` alone is an error, and `use std/fx.{echo, room_reverb}` adds just those two effects to your piece (any module can be used this way; functions and constants always come with it). Effects that read `in`: `lowpass`, `highpass`, `bandpass`, `band_cut`, `equalizer`, `echo`, `room_reverb`, `glitch`, `ensemble`, `swirl` (a phaser), `tremolo`, `compressor`, `overdrive`, `lofi` and `soft_clip` (rounds off peaks with no delay). Each has typed, ranged parameters and, where it makes sense, a `mix`. `compressor` has a `knee` and a `link` (at 1 the loudest channel decides the squeeze for all, so a stereo image stays put), `overdrive` runs at twice the sample rate so it doesn't alias. There is no limiter among them: a lookahead limiter delays the sound, so it belongs once, at the end, and the master already has one. `glitch` chains six glitches on the same sound, each switched on by its own control: a stutter that repeats the last piece (and rolls faster the longer it is held, when `stutter_shrink` is below 1; `stutter_gate` cuts each repeat short, `stutter_reverse` plays it backwards, `stutter_shape` fades it out or swells it in, `stutter_damp` darkens each repeat more than the last, `stutter_attack` and `stutter_bend` shape each repeat's envelope, and `stutter_accent` softens every second repeat), a rewind that plays it backwards, a slow-down like a stopping tape, a scatter that cuts the last bar into `scatter_slices` and plays them shuffled (a new shuffle each pass, the same `scatter_seed` giving the same shuffles every time, `scatter_reverse`, `scatter_repeat`, `scatter_drop` and `scatter_detune` the chance a slice runs backwards, is swapped for another, drops out, or is pitched up or down), a freeze that hangs the last `freeze_length` of sound in the air as a cloud of grains (`freeze_spread` smears it, `freeze_pitch` and `freeze_detune` bend it), and a bit-and-rate crush. Set `scatter_length` to a bar of your tempo. The `gate` control starts open: a row of steps for it in a clip is a trance gate (`x` lets the sound through, `.` cuts it), rounded by `gate_attack` and `gate_release`. A gate is best drawn in a gesture clip, which has a step for every sixteenth whatever else is playing, so it chops a held sound too. With every control at zero the sound passes through untouched. The pieces are the opcodes `repeat_last`, `rewind_last`, `slow_down`, `scatter` and `freeze` (`x.repeat_last(hold:, length:)`, see the [opcode list](/reference/opcodes/)), and the function `apply`, which needs no `use` and runs any function on a sound as much as a control says (`x.apply(fn(s) { s.bitcrush(bits: 5) }, when: crush)`), so a filter, a reverb throw or a gain dip can be a stage in the chain too. Each fades in and out over `blend` (3ms by default) so a hold starts and ends without a click. Like the instruments, each stands alone: read the module for the controls of each one. A clip draws when each control is on with [lanes for an effect](/reference/language/patterns/#lanes-for-an-effect). The tracker lists them under **+ Add effect…** and beside **+** in its effects library.

```nml
use std/fx
```

## Writing your own

Anything in these files can be copied and changed. A module you write goes next to your project or in `lib/`; see [Modules](/reference/language/modules/). If it turns out well, tell us: the library grows by what people need.
