**Compiled by niminal.** These modules are ordinary source, compiled by the server — and offered as presets in the tracker.

The modules under `std/` come with niminal. They are ordinary niminal source, read from the program itself, so `use std/filters` works anywhere and nothing needs installing. They are also the best examples of what [functions](/reference/language/functions/) can do, so read them: they are short.

```nml
use std/filters
use std/reverb

instr pad(freq: hz) {
  out = osc(saw, freq).ladder(cutoff: 900hz, res: 0.4)
  out += out.fdn(time: 2.5sec) * 0.3
}
```

A function from a module is called like any other, as a method or with the signal first. Parameters marked `init` are read when a note starts. The ratios and other tables the functions use are public too (`drum_modes`, `fdn_lengths`, and so on), so you can use them or write your own.

## std/filters

| Function | What it is |
| --- | --- |
| `ladder(x, cutoff, res: 0.3)` | A four-pole low-pass with a `tanh` in each stage, like a transistor ladder. `res` near 1 rings and then sings at the cutoff. Loud input saturates the stages, as it should. |
| `biquad_lp(x, cutoff, q: 0.7071)` | A two-pole low-pass. `q` is the height of the peak at the cutoff; 0.707 is flat. |
| `biquad_hp(x, cutoff, q: 0.7071)` | A two-pole high-pass. |
| `biquad_bp(x, cutoff, q: 1)` | A two-pole band-pass with a peak gain of 1. |
| `biquad_notch(x, cutoff, q: 1)` | Everything except a band around the cutoff. |
| `onepole_lp(x, cutoff)`, `onepole_hp(x, cutoff)` | One pole: 6db an octave. |
| `biquad(x, b0, b1, b2, a1, a2)` | One biquad section from its coefficients, for building your own. |

## std/physical

| Function | What it is |
| --- | --- |
| `string(x, freq: init hz, decay: 0.996, size: 4096)` | A plucked string (Karplus-Strong). Feed it a short, bipolar burst such as `noise() * env[1 4ms 0]`; a click with only positive values gives a string that only drifts. `size` is the longest period, in samples. |
| `modal(x, freq: init hz, ratios, decay: 0.9995)` | A resonator for each of `ratios` times `freq`, in parallel. Keep `freq * ratio` below half the sample rate. |
| `drum(x, freq: init hz, decay: 0.999)` | The first eight modes of a circular membrane. |
| `free_bar(x, freq: init hz, decay: 0.9997)` | A free bar, as in a glockenspiel. |
| `bell(x, freq: init hz, decay: 0.9998)` | A bell, with a hum an octave below the strike note. |

```nml
use std/physical
instr tom(freq: hz = 110hz) { (impulse(1hz) * 0.5).drum(freq) }
```

## std/delays

| Function | What it is |
| --- | --- |
| `multitap(x, times, gains, max: 96000)` | Echoes at several times, from one delay line. `x.multitap([120ms, 250ms, 410ms], [0.6, 0.4, 0.3])` gives `x` plus the echoes. `max` is the longest time in samples. |
| `tape(x, time, feedback: 0.5, damp: 4khz, max: 96000)` | A feedback delay with a low-pass in the loop, so each repeat is darker. |

## std/reverb

| Function | What it is |
| --- | --- |
| `fdn(x, time: init 2sec, damp: init 5khz, size: init 1)` | A feedback delay network: eight delay lines of mutually prime lengths mixed by a Hadamard matrix. It runs natively (it is the `fdn_reverb` opcode, wrapped here for its names and ranges), at a small fraction of a core. `time` is how long the tail takes to fall by 60db, `damp` the cutoff of the low-pass in each line, and `size` (0.5 to 2) stretches the lines. Mono in, mono out, and wet only: mix it with the dry yourself. |

A tail costs about 3% of one core, so one on a bus is cheap.

## std/spectral

These use [`frames`](/reference/language/functions/#frames-and-the-fft), so each is `size` samples late (1024 unless you give `size`); the compiler delays the path beside it to match.

| Function | What it is |
| --- | --- |
| `band_keep(x, lo: 0, hi: 0.25, size: 1024)` | Keeps the part of the spectrum from `lo` to `hi`, as fractions of the way to half the sample rate. |
| `robot(x, size: 1024)` | Keeps every magnitude and zeroes every phase: a buzz at the frame rate. |
| `blur(x, amount: 0.9, size: 1024)` | Mixes each spectrum with the ones before it: a long wash. |
| `denoise(x, threshold: 0.01, size: 1024)` | Silences the bins quieter than `threshold`: a spectral noise gate. |

## std/instruments

Finished instruments with a few controls each, for when you want a sound and not a function. `use std/instruments`, then play them by name (`instrument: kick`, or `kick(freq: c2) for 1beat`). Each is complete on its own, so you can copy one into your file and change it. The tracker offers the same list under **▾** beside **+** in its instruments. A comment line `// folder: drums/kicks` between definitions files the ones after it under that folder in the tracker's preset browser.

| Instrument | What it is |
| --- | --- |
| `kick(freq: 55hz, punch, decay)` | A sine that drops in pitch, with a click on the front. |
| `snare(freq: 180hz, snap, decay)` | A short triangle thump under band-passed noise. |
| `hat(open)` | High-passed, crushed noise; `open` goes from a tick to a wash. The note's pitch is ignored. |
| `bass(freq, cutoff: 600hz, res)` | A saw with a sine an octave down, through a low-pass. |
| `pluck(freq, tone, decay)` | A plucked string that is bright at the start and dulls as it dies away. |
| `pad(freq, attack, release, detune)` | Three slightly detuned saws, softened by a low-pass, with a slow envelope. |
| `lead(freq, cutoff: 2500hz, vibrato)` | A saw with vibrato, through a low-pass. |
| `bell(freq, decay)` | A struck bell from two sines, one bending the phase of the other. |

## std/drums

A drum machine voice and twenty-one presets of it. `drum` is a function with the controls of a drum voice: an oscillator (`wave` sine, tri, square or saw; `freq`, `attack`, `decay`) with a pitch modulation (`mod_mode` `drop`, `wobble` or `random`; `mod_amount` in semitones, `mod_rate`), a noise source with its own filter (`noise_filter` low, band or high; `noise_freq`, `noise_q`) and envelope (`noise_shape` `soft`, `linear` or `burst`; `noise_attack`, `noise_decay`), a `mix` between the two, `drive`, one EQ band (`eq_freq`, `eq_gain`) and `amp`, and a velocity: `vel` (how hard the note is played) with `osc_vel`, `noise_vel` and `mod_vel` saying how much it changes the oscillator, the noise and the pitch modulation. The choices shape the instrument and are fixed when it is compiled; the numbers stay live. The output is soft-clipped, so every setting is bounded.

`use std/drums`, then play a preset by name, or call `drum(...)` inside an instrument of your own. Each preset takes the note as a tuning (`c3` plays it as designed), takes the note's `gain` as its velocity, and exposes the same numeric controls, so any lane can reshape any sound. The hats share a choke group, so a closed hat ends an open one.

| Presets | |
| --- | --- |
| `kick_deep`, `kick_808`, `kick_punch`, `kick_click`, `kick_dirty` | Kicks from a long sub to a hard, driven one. |
| `snare_tri`, `snare_tight`, `snare_fat` | Snares with a triangle body and band-passed noise. |
| `clap`, `clap_room` | Noise chopped into bursts, dry and with a long tail. |
| `hat_closed`, `hat_open`, `hat_tick` | Hi-hats from high-passed noise. |
| `tom` | A tom; play different notes for a set. |
| `rim`, `cowbell` | Square-wave percussion: a rim shot and a driven cowbell. |
| `zap`, `blip`, `wobble_bass`, `sweep`, `crash` | Effects: a laser, random-pitch bubbles, a slow wobble, a rising noise band, a cymbal. |

Keep a preset's name different from the choice words above (a preset called `wobble` would quietly stop a file playing), and from the instruments in `std/instruments`. The tracker lists these under **▾** beside **+** in its instruments; adding one copies the `drum` function into the project with it, so the copy stands alone.

## std/fx

Effects that read `in`: `lowpass`, `highpass`, `bandpass`, `band_cut`, `equalizer`, `echo`, `room_reverb`, `glitch`, `ensemble`, `swirl` (a phaser), `tremolo`, `compressor`, `overdrive`, `lofi` and `ceiling` (a limiter). Each has typed, ranged parameters and, where it makes sense, a `mix`. `compressor` has a `knee` and a `link` (at 1 the loudest channel decides the squeeze for all, so a stereo image stays put), `overdrive` runs at twice the sample rate so it doesn't alias, and `ceiling` is a true lookahead limiter: nothing passes the ceiling, whatever the release. `glitch` chains four glitches on the same sound, each switched on by its own control: a stutter that repeats the last piece (and rolls faster the longer it is held, when `stutter_shrink` is below 1), a rewind that plays it backwards, a slow-down like a stopping tape, and a bit-and-rate crush. With every control at zero the sound passes through untouched. The pieces are the functions `repeat_last`, `rewind_last` and `slow_down`, which you can call yourself with `use std/glitch` (`x.repeat_last(hold:, length:)`), and `apply`, which runs any function on a sound as much as a control says (`x.apply(fn(s) { s.bitcrush(bits: 5) }, when: crush)`), so a filter, a reverb throw or a gain dip can be a stage in the chain too. Each fades in and out over `blend` (3ms by default) so a hold starts and ends without a click. That module is only the functions, so it adds no effects to your piece. Like the instruments, each stands alone: read the module for the controls of each one. A clip draws when each control is on with [lanes for an effect](/reference/language/patterns/#lanes-for-an-effect). The tracker lists them under **+ Add effect…** and beside **+** in its effects library.

```nml
use std/fx
```

## Writing your own

Anything in these files can be copied and changed. A module you write goes next to your project or in `lib/`; see [Modules](/reference/language/modules/). If it turns out well, tell us: the library grows by what people need.
