**Compiled by niminal.** These modules are ordinary source, compiled by the engine.

The modules under `std/` come with niminal. They are ordinary niminal source, read from the program itself, so `use std/physical` works anywhere and nothing needs installing. They are also the best examples of what [functions](/reference/language/functions/) can do, so read them: they are short.

```nml
instr pad(freq: hz) {
  out = osc(saw, freq).ladder(cutoff: 900hz, res: 0.4)
  out += out.fdn_reverb(time: 2.5sec) * 0.3
}
```

A function from a module is called like any other, as a method or with the signal first. Parameters marked `init` are read when a note starts. The ratios and other tables the functions use are public too (`drum_modes`, `free_bar_modes`, and `bell_modes`), so you can use them or write your own.

## Building blocks that are opcodes

The filters, resonators and reverbs everything else is made of run natively and need no `use`; the [opcode list](/reference/opcodes/) has each one.

| Opcode | What it is |
| --- | --- |
| `onepole_lp(x, cutoff)`, `onepole_hp(x, cutoff)` | Complementary one-pole filters, 6db per octave. Cutoff is clamped to 0..Nyquist. No import. |
| `ladder(x, cutoff, res: 0.3, drive: 1)` | A four-pole low-pass with a `tanh` in each stage, like a transistor ladder. `res` near 1 rings and then sings at the cutoff. Loud input, or a higher `drive`, saturates the stages, as it should. |
| `biquad_lp`, `biquad_hp`, `biquad_bp`, `biquad_notch`, `biquad_allpass` `(x, cutoff, q)` | Two-pole sections. `q` is the height of the peak at the cutoff; 0.707 is flat. |
| `biquad(x, b0, b1, b2, a1, a2)` | One biquad section from its coefficients, for building your own. |
| `modal(x, freq, ratios, decay: 300ms)` | A resonator for each of `ratios` times `freq`, in parallel: bars, bells and drums. |
| `delay(x, time, feedback, damp)` | A delay line; `damp` darkens each echo, like a tape delay. |
| `fdn_reverb(x, time, damp, size)` | A feedback delay network of eight lines. |
| `spectral_warp(x, shift: 0, size: 2048, overlap: 4, formant: 0, preserve: 0, transients: 1, detail: 32)` | Peak-locked pitch shifting with independent spectral-envelope control and local attack resets. Shift and formant are semitones (−48 to +48). |

## std/physical

| Function | What it is |
| --- | --- |
| `string(x, freq: init hz, decay: 0.996, damp: 0.5, max: 50ms)` | A plucked string (Karplus-Strong): `comb` with the delay tuned to the pitch. Feed it a short, bipolar burst such as `noise() * env[1 4ms 0]`; a click with only positive values gives a string that only drifts. `decay` near 1 rings longer, `damp` is how fast the highs die away, and `max` is the longest period (the lowest `freq` is 1 / `max`). |
| `membrane(x, freq: init hz, decay: 150ms)` | The first eight modes of a circular membrane. |
| `free_bar(x, freq: init hz, decay: 500ms)` | A free bar, as in a glockenspiel. |
| `bell(x, freq: init hz, decay: 750ms)` | A bell, with a hum an octave below the strike note. |

These are `modal` with a set of ratios; `modal` is an opcode.

```nml
use std/physical
instr tom(freq: hz = 110hz) { (impulse(1hz) * 0.5).membrane(freq) }
```

## Sustained bowed and reed instruments

`bowed` and `reed` are native sources and need no import. Both keep a resonating waveguide alive while a nonlinear bow or reed excites it. Their controls run from 0 to 1 and ease over 2ms; moving a control does not restart the string or bore.

For playable instruments with attack and release, take the presets:

```nml
use std/instruments.{bowed_string, reed_wind}

bowed_string(freq: a3, pressure: 0.7, position: 0.25, speed: 0.6) for 2beats
at +2beats reed_wind(freq: c4, pressure: 0.65, stiffness: 0.5, breath: 0.1) for 2beats
```

Pressure, speed and position change the bowed string's stick-slip behavior; pressure, stiffness and breath shape the clarinet-like reed tone. Brightness changes losses inside either resonator. Some extreme combinations whistle, overblow or stop speaking; pressure is an excitation control, not a volume fader.

For custom instruments, envelope the excitation and output explicitly:

```nml
instr bowed_pad(freq: hz, pressure: 0..1 = 0.7) {
  level = env[0 60ms 1 | 300ms 0]
  bowed(freq, pressure: pressure, velocity: level * 0.6) * level * 0.8
}
```

`bowed` supports 20 Hz up to the smaller of 3000 Hz and `sample_rate / 12`; `reed` supports 20 Hz up to the smaller of 4000 Hz and `sample_rate / 16`. Positive frequencies outside that range clamp to its bounds; nonpositive or non-finite frequencies produce silence. Other controls clamp to 0…1, with non-finite values treated as zero. A stopped excitation lets existing energy decay. Use an output envelope to finish a note promptly.

The nonlinear models run at the session rate. `oversample(2) { ... }` or `oversample(4) { ... }` can reduce aliasing at extra CPU cost and conversion latency. These are compact synthetic string/wind models, with a loss filter rather than a sampled violin body or a complete acoustic instrument.

## std/delays

For echoes at times of your own, add `delay`s: `x + x.delay(120ms) * 0.6 + x.delay(250ms) * 0.3`. Each is its own delay line, so each tap can have its own time, be modulated (`x.delay(250ms + lfo(0.3hz) * 5ms, max: 300ms)`), be filtered or be panned.

| Function | What it is |
| --- | --- |
| `echoes(x, count: 4, spacing: 120ms, fade: 0.6)` | `x` followed by `count` echoes, `spacing` apart, each `fade` times the level of the one before. |
| `dark_echo(x, time, feedback: 0.5, damp: 4khz, max: 2sec)` | `x` plus a feedback delay with a low-pass in the loop, so each repeat is darker. |

## std/blocks

Building blocks to wire together, in the manner of modules in a rack. A block takes signals in, so a grid, an envelope or a random signal can drive any of its parameters.

| Function | What it is |
| --- | --- |
| `scan_weights(count, centre: 0.5, width: 1)` | Normalized triangular weights for a spectral window or mixer. `centre` runs from first member (0) to last (1); `width` is in members. Width 1 crossfades neighbours. Empty arrays have no weights. |
| `scan_mix(signals, centre: 0.5, width: 1)` | Scan across an array of signals: oscillators, partials or effect returns. Weights sum to one, so scanning identical inputs preserves their level. Empty inputs return silence. |
| `harmonic_bank(freq, gates, count: 16, brightness: 0.5, odd_even: 0, gate_smooth: 4ms, centre: 0.5, width: 2, focus: 0)` | A harmonic oscillator with named outputs `mixed` and `partials`. Brightness tilts the series; odd/even balance selects its families. `focus` moves from the whole series to a window whose position and breadth are set by `centre` and `width`. |
| `harmonic_osc(...)` | The mixed output of `harmonic_bank`, with the same parameters. Gates open individual partials; missing gates stay open. |
| `function_gen(cycle: 8, rise: 0.5, curve: 1)` | A shape from 0 up to 1 and back, `cycle` beats long, rising for the first `rise` of it (a share) and falling for the rest. `curve` bends both sides: above 1 holds back at the bottom, below 1 hurries away from it. It follows the transport, so it always peaks on the same beat. |
| `contour(trigger: 0, rise: 10ms, fall: 300ms, curve: 1, cycle: 0)` | A triggered rise/fall shape with named outputs `value`, `eor` and `eoc`. Retriggers rise from the present level; cycling finishes its current shape when switched off. |
| `wobble(beats: 0.5, shape: stepped, seed: 0)` | Random values from -1 to 1, a new one every `beats` beats. `stepped` holds each until the next; `smooth` slides to it. The same `seed` is the same run every time. |
| `clock_div(beats: 1, width: 0.5)` | A gate that follows the transport: high for the first `width` of every `beats` beats. `clock_div(3/2)` drifts against the bar and meets it again. |
| `echo_loop(x, time: 3/16beat, feedback: 0.5, filter: 3khz, duck: 0, ping_pong: off, max: 2sec)` | The echoes of `x` and nothing else, to blend with the dry sound: `x.crossfade(x.echo_loop(...), mix)`. `time` follows the tempo; `filter` is a low-pass in the loop, so each repeat is darker; `duck` pulls the echoes down while `x` is loud; `ping_pong: on` bounces them between left and right, the first on the right. `max` must be at least twice `time` for a ping-pong. |
| `stereo_echo(x, time: 3/16 * clock.beat_length, feedback: 0.5, colour: 0.5, skew: 0.25, diffusion: 0.2, motion: 0.1, duck: 0, max: 4sec)` | Wet-only stereo repeats. Skew offsets left/right times, colour sets feedback brightness, diffusion smears the returns, motion bends their pitch gently, and duck clears space for new audio. |
| `space_reverb(x, size: 0.5, decay: 0.65, absorption: 0.4, diffusion: 0.7, motion: 0.2, rate: 0.07hz, predelay: 20ms, tilt: 0, duck: 0)` | Wet-only stereo space with a moving tank, absorption, diffusion, tone tilt and ducking. Size changes bend the existing tail. |
| `multimode_filter(x, cutoff: 1khz, res: 0.2, drive: 0)` | A state-variable filter with outputs `low`, `band`, `high` and `notch` at once. Stable at any cutoff and resonance, even modulated at audio rate; stereo input is filtered channel by channel. It saturates as resonance passes 0.6, so it can ring at 1 without running away. `drive` thickens it at any resonance. |
| `low_pass_gate(x, ping: 1, level: 0, decay: 400ms, res: 0.1, mode: both)` | A filter and amplifier opened together by one control, so a sound darkens as it fades. `ping` strikes it on each rising edge (the default strikes once as a note starts); `level` holds it open. `mode` is `both`, `filter` or `gate`. Outputs `sound` and `opening` (0..1). |
| `complex_osc(freq, ratio: 2, index: 1, am: 0, fold: 0, symmetry: 0)` | A sine modulator at `ratio` times `freq` bends the main sine's phase (`index`, radians) and rings it (`am`); then a sine fold (`fold`, tipped by `symmetry`) that eases off above 2khz. Outputs `sound` (never past ±1.2) and `modulator`. |
| `shift_random(clock: 0, lock: 0.75, length: 8, seed: 0)` | A looping random sequence: each rising edge of `clock` steps through `length` stored values, and `lock` is the chance of keeping each one (1 loops exactly, 0 is always new). Outputs `value` (-1..1) and `gate` (high with the clock on steps whose value is above 0). |
| `texture(source, position: 0.5, size: 100ms, density: 20hz, pitch: 0, spread: 0.2, detune: 0, width: 0.5, gain: 1, seed: 0)` | A cloud of grains cut from a sample or table, held to safe ranges (grains 5ms to 500ms, 1 to 100 a second) and scaled down as they overlap, so a thick cloud is no louder than a thin one. `position` is where grains start, `spread` scatters them, `pitch` and `detune` are semitones. Scan the source by moving `position`. |
| `quantize(note, scale: [0, 2, 4, 5, 7, 9, 11], root: 0, amount: 1)` | Snaps a note number (semitones) to the nearest note of `scale`, which lists one octave of notes. A note exactly between two goes to the lower one. Works on any value: quantize a random loop into a melody. |
| `vocoder(carrier, modulator, bands: 16, low: 120hz, high: 8khz, width: 3, attack: 4ms, release: 40ms, hiss: 0.3)` | A channel vocoder: each band of `modulator`'s loudness shapes the same band of `carrier`. `hiss` lets consonants through as noise. Stereo inputs are mixed to mono. |
| `cross_mod(a, b, mode: ring, amount: 0.5) -> (sound, aux)` | Two signals into one: `ring`, `fold` (b pushes a into a wavefolder) or `diode`. `amount` blends from `a` to the effect; `aux` is the plain product. Inputs are held to ±16 and `sound` to ±1.2. |
| `slew(x, rise: 10ms, fall: 100ms, shape: smooth)` | Follows any signal with separate rise and fall times: portamento, a gate turned into an envelope, stepped random smoothed. `linear` takes the time to travel 1.0 at a steady rate. A time of 0 follows at once. |
| `morph_osc(freq, shape: 0, width: 0.5) -> (sound, sub)` | A band-limited oscillator that morphs sine, triangle, saw, pulse (0 to 1); `width` is the pulse duty cycle. `sub` is a sine an octave down. Within ±1.3. |
| `wavefolder(x, amount: 0.3, symmetry: 0)` | Two folds in a row, the second gentler: a plain tone gains overtones. `symmetry` adds even harmonics. Aliases when pushed; wrap it in `oversample(4) { ... }` for a cleaner sound. Within ±1.2. |
| `multi_lfo(rate: 1hz, shape: 0.5, smooth: 0.5, shift: 0.25) -> (a, b, c, d)` | One low-frequency oscillator with four outputs `shift` cycles apart, from -1 to 1. `shape` is where the peak falls, `smooth` rounds it towards a sine. |
| `formant_filter(x, freq: 600hz, span: 0.5, res: 0.6, tilt: 0) -> (sound, low, mid, high)` | Three band-pass peaks that move together, so a sound takes on vowels. `span` spreads the upper two, `tilt` favours low or high. Each peak is also an output. |
| `random_source(clock: 0, spread: 0.5, bias: 0, steps: 1, deja_vu: 0.5, density: 1, length: 8, seed: 0) -> (value, gate)` | A random source for tunes and rhythms: a loop of `length` draws, `deja_vu` the chance of keeping each (1 repeats the loop). `spread` and `bias` shape the values live; `steps` 1 holds each value and lower glides; `density` thins the gates. |
| `multi_voice(freq, model: 0, timbre: 0.5, harmonics: 0.5, morph: 0.5)` | One voice, five models (analog, FM, additive, vowel, folded) blended by `model`, with three controls that do the most useful thing for each. Every model runs, so it costs about five voices. Within ±1.5. |

```nml
use std/blocks

instr additive(freq: hz) {
  gates = grid {
    1: x... x... x... x...
    2: ..x. ..x. ..x.
    3: x.x. ...x x.
  }.over(1bar).width(55%)
  harmonic_osc(freq, gates: gates, brightness: 0.6).pan(angle: 0deg) * env[0 3ms 1 | 120ms 0]
}
```

The last four are voice modules: each parameter takes a signal, so one module can drive another, and none can be set to anything that blows up. Their named outputs can share a name with your controls.

```nml
use std/blocks

instr bongo(freq: hz) {
  steps = shift_random(clock: clock_div(1/4), lock: 0.9, seed: 4)
  voice = complex_osc(freq * (1 + steps.value.max(0)), ratio: 1.5, index: 2, fold: 0.3)
  gated = voice.low_pass_gate(ping: steps.gate, decay: 180ms)
  gated.sound.multimode_filter(cutoff: 300hz + gated.opening * 3khz, res: 0.7).band * env[1 | 50ms 0]
}
```

`function_gen`, `wobble` and `clock_div` read the transport (`clock.beat`, `clock.bpm`), so they follow the tempo as it changes. Their outputs are plain signals: scale one with `.range(...)`, multiply it into a gain or add it to a control.

Partials above 45% of the sample rate are left out, and the sum is scaled by the loudest the series could be, so it never exceeds 1 however the controls are set.

### Playing the spectrum

`centre` runs from the fundamental to the highest configured partial; `width` is measured in partials.
Raise `focus` to reveal this window within the complete spectrum. At full focus and width 1,
scanning crossfades between individual harmonics. Brightness and odd/even balance still shape the window;
a window over excluded harmonics is silent. Gate values clamp to 0…1 before smoothing.

The bank's partials share the mixed output's normalization, so their sum reproduces `mixed`.
They are ready for separate filtering, articulation or panning. Scanning those partials again produces
a weighted average, so a highlighted layer may need additional gain.

```nml
use std/blocks.{harmonic_bank, scan_mix, function_gen}

instr spectrum(freq: hz) {
  position = function_gen(cycle: 16, rise: 0.75)
  voice = harmonic_bank(freq, centre: position, width: 3, focus: 0.7)
  highlight = scan_mix(voice.partials, centre: position, width: 1)
  (voice.mixed * 0.2 + highlight * 0.3) * env[0 5ms 1 | 300ms 0]
}
```

### Triggered and cycling shapes

`contour` responds to positive edges. An initially positive trigger starts it immediately; holding that
trigger high produces one rise and fall. A new edge reverses a fall into a rise from its current level,
without jumping back to zero. Rise and fall are full-scale travel times: retriggering halfway up takes
half the rise time to reach the peak. Each time clamps to 0…60sec; zero takes one sample.

`curve` bends the output, leaving the timing unchanged. At 1 it is linear, above 1 it spends more time
near zero, and below 1 it opens quickly. With `cycle` above zero, an idle contour starts immediately
and repeats. Turning cycling off lets the current contour finish. These cycles follow their own state;
use `function_gen` when a shape must instead follow a fixed position in the transport.

`eor` and `eoc` are one-sample pulses when the rise and fall finish. Pass them directly to another
contour's trigger at audio rate; sampling them at control rate can miss pulses.

```nml
use std/blocks.{contour, harmonic_osc}

instr breathing(freq: hz) {
  breath = contour(cycle: 1, rise: 2sec, fall: 1sec)
  accent = contour(trigger: breath.eor, rise: 10ms, fall: 400ms, curve: 2)
  harmonic_osc(freq, brightness: 0.2 + breath.value * 0.6,
    centre: accent.value, focus: 0.7) * env[0 10ms 1 | 300ms 0] * 0.2
}
```

### Stereo echoes

`stereo_echo` returns only the processed sound. Add it as a send return, or crossfade it with the dry signal:

```nml
use std/blocks.{stereo_echo}

fx space {
  echoes = in.stereo_echo(time: 3/16beat, skew: 0.3, colour: 0.55, diffusion: 0.4, motion: 0.2)
  out = in + echoes * 0.25
}
```

`skew` ranges from −1 to 1 and offsets the left and right times by up to half of `time` in opposite
directions. Mono feeds both sides; stereo keeps its channels. Wider inputs use their first and last channels.
The two feedback lines are independent. `colour` runs from dark (400hz) to bright (16khz), filtering inside
each feedback loop. The first echo retains the source's colour; subsequent repeats become darker.
`diffusion` crossfades the wet signal through two fixed allpass stages **after** the feedback loops.
`motion` adds two slow read-head modulations, each up to 3ms. It is movement of delay time, not a chorus added afterwards.
Time changes use the engine's smoothed, speed-limited read heads and bend pitch. Times clamp to 1ms…`max`;
leave room for skew and motion when choosing `max`. Feedback clamps to 0…0.95. Ducking follows the louder input channel, so opposite-polarity stereo audio still ducks.

### Moving space

`space_reverb` returns a processed stereo signal to add to a dry bus. `size` changes the tank geometry
without clearing its contents; moving it bends the tail's pitch. `motion` adds a sinusoidal movement of
up to 0.02 in size, at `rate` (0.01…4hz). Near the size limits, that motion clips to the available range.
`decay` sets feedback, `absorption` removes high frequencies from the circulating tail, and `diffusion`
changes scattering in the tank. Decay is a normalized feedback control, not seconds or an infinite hold.

Predelay delays the whole input to the space, including its early reflections, by 0…200ms. Zero uses
the delay primitive's minimum of one sample. `tilt` shapes the return with low and high shelves at 300hz
and 3khz: positive values lift treble and reduce bass, by up to roughly 6db each. `duck` follows the louder
input channel and attenuates the return while the source is loud. Both echo and space ducking use a
5ms attack and 200ms release.

```nml
use std/blocks.{space_reverb, contour}

fx breathing_space {
  shape = contour(cycle: 1, rise: 8sec, fall: 4sec)
  wet = in.space_reverb(size: 0.4 + shape.value * 0.2, decay: 0.7,
    absorption: 0.5, motion: 0.3, tilt: -0.2, duck: 0.4)
  out = in + wet * 0.2
}
```

The rig example combines spectral scanning, a separately panned harmonic highlight, moving stereo
echoes and a breathing space. Its source is `examples/rig.nml`. CC 10 moves the spectral centre,
CC 11 sets focus, CC 12 changes space size, and CC 13 sets reverb return level. The `bloom` macro
moves these alongside brightness, density and echo level. A cycling contour moves echo diffusion
and space size; its end-of-rise pulse triggers a second contour that changes the return's tone.

## std/spectral

These effects analyze overlapping spectral frames. Each is `size` samples late (1024 unless listed otherwise); the compiler delays parallel dry paths to match. The frame helpers remain available for writing custom processing.

| Function | What it is |
| --- | --- |
| `band_keep(x, lo: 0, hi: 0.25, size: 1024)` | Keeps the part of the spectrum from `lo` to `hi`, as fractions of the way to half the sample rate. |
| `robot(x, size: 1024)` | Keeps every magnitude and zeroes every phase: a buzz at the frame rate. |
| `blur(x, amount: 0.9, size: 1024)` | Mixes each spectrum with the ones before it: a long wash. |
| `denoise(x, threshold: 0.01, size: 1024)` | Silences the bins quieter than `threshold`: a spectral noise gate. |
| `spectral_envelope(re, im, detail: 32)` | Smooths real FFT magnitudes in the log domain using a triangular cepstral lifter; returns an envelope array for use inside a frame callback. Adds no frame latency itself. |
| `envelope_transfer(carrier, donor, amount: 1, detail: 32, size: 1024)` | Applies the donor's broad spectral shape to the carrier, retaining the carrier's phase and fine structure. |
| `phase_frequency(phase, size: 2048, hop: 512)` | Stateful phase unwrapping: real-FFT phases in radians to instantaneous frequencies in cycles/sample. Call once per frame with the matching FFT size and hop. |
| `phase_accumulate(frequency, size: 2048, hop: 512)` | Stateful integration of cycles/sample into wrapped synthesis phases in radians. Call once per frame with the matching size and hop. |

`spectral_warp` is a native opcode and needs no import. It moves complete peak regions, sums overlapping regions and preserves relative phases around each peak. `transients` controls local phase resets on spectral growth (0 off, 1 full); FFT windowing can still smear attacks. `preserve: 1` retains the original broad spectral envelope as pitch changes, while `formant` shifts that envelope independently. Envelope correction is limited to 32× gain per bin, so leave headroom. Stereo channels are independent. Neutral settings reconstruct the source with the declared latency.

The built-in `spectral_memory` captures a fixed ring of spectral frames, then holds or scans them when recording stops. It shares pitch, formant and preservation controls with `spectral_warp`. See [Spectral processing](/reference/language/spectral/) for controls, storage limits and examples.

Additional native spectral tools need no import: `partial_morph` pairs persistent tonal tracks and glides their pitches across different FFT regions; `spectral_morph` blends two sources' magnitudes and frequencies independently; `spectral_thin` retains the strongest bins; `spectral_arp` focuses a moving spectral region; `spectral_hold` freezes magnitude and frequency separately; `spectral_shift` adds Hz above a cutoff; and `spectral_partials` tracks peaks into an interpolated sine bank. See [Spectral processing](/reference/language/spectral/) for controls, latency, limitations and musical examples.


For envelope transfer, `amount: 0` returns the carrier delayed by one frame, and `1` applies the full transfer. The donor's level affects the result; a silent donor silences full transfer. Per-bin gain is capped at 32× (about 30 dB), and log magnitudes are floored at `size * 0.000001` to keep quiet bins stable. Leave output headroom. This shapes existing carrier energy; it cannot supply partials absent from the carrier or separate pitch from formants perfectly.

`detail` is a compile-time integer: larger values retain narrower spectral features, smaller values give a smoother envelope, and values below 1 act as 1. Its audible bandwidth depends on the sample rate; start around 32 at 48 kHz. FFT size also controls frequency resolution and latency. This is frame-based processing, so sharp attacks can smear.

[The envelope-transfer example](https://github.com/martineastwood/niminal/blob/main/examples/envelope_transfer.nml) introduces a warm carrier and a rhythmic noise breath, then plays their hybrid through an A-minor/F-major progression, without external samples.

## std/instruments

Twenty melodic instruments, with controls chosen for each sound. `use std/instruments.{bass, electric_piano}`, then play by name (`electric_piano(freq: c4, gain: -6db) for 1beat`). The note's `gain` controls loudness and also shapes brightness or excitation: softer playing changes the sound, not just its level. Percussive sounds such as `pluck` and `bell` ring for their decay; sustained sounds follow note-off and their release.

| Instrument | Sound and controls |
| --- | --- |
| `bass` | Saw and sub sine; `cutoff`, `res`. |
| `pluck` | A bright subtractive pluck; `tone`, `decay`. |
| `pad` | Three detuned saws; `attack`, `release`, `detune`. |
| `lead` | A filtered saw lead; `cutoff`, `vibrato`. |
| `bell` | A struck phase-modulated bell; `decay`. |
| `bowed_string` | A sustained waveguide string; `pressure`, `position`, `speed`, `brightness`, `attack`, `release`. |
| `reed_wind` | A sustained reed bore; `pressure`, `stiffness`, `breath`, `brightness`, `attack`, `release`. |
| `electric_piano` | Warm body and struck tine; `tone`, `tine`, `bark`, `decay`, `release`. |
| `organ` | Drawbar-style additive organ; `drawbar`, `percussion`, `vibrato`. |
| `pwm` | Moving pulse width through a ladder filter; `width`, `motion`, `rate`, `tone`. |
| `fm_keys` | Two-operator FM keyboard; `ratio`, `index` (radians), `contour`, `decay`, `release`. |
| `struck_string` | Noise-excited, pitch-compensated comb string; `ring`, `tone`, `release`. |
| `metal_bar` | A struck bank of inharmonic bar modes; `tone`, `decay`. |
| `morph_pad` | Morphing harmonic wavetables; `colour`, `motion`, `attack`, `release`. |
| `west_coast_pluck` | `complex_osc` struck through `low_pass_gate`: darkens as it fades; `ratio`, `index`, `fold`, `decay`. |
| `harmonic_drone` | `harmonic_osc` whose emphasis a `shift_random` loop moves; `beats`, `lock`, `focus`, `brightness`, `attack`, `release`. |
| `rubber_bass` | `complex_osc` with its modulator an octave down through a driven `multimode_filter`; `growl`, `cutoff`, `sweep`, `res`, `drive`. |
| `wandering_voice` | A melody that plays itself: a `shift_random` loop snapped to a `scale` by `quantize`, played by `complex_osc` through `low_pass_gate`; `scale` (0 pentatonic, 1 major, 2 minor), `range`, `beats`, `lock`. |
| `ring_bell` | Two sines multiplied through `cross_mod`; `ratio`, `metal`, `mode` (0 ring, 0.5 wavefold, 1 diode), `decay`. |
| `macro_voice` | `multi_voice`: `model` moves through analog, FM, additive, vowel and folded; `timbre`, `harmonics`, `morph`, `attack`, `release`. |

`std/instruments`, `std/drums` and `std/fx` are shelves: take presets by name, rather than importing the whole shelf. Each copied preset stands alone: one wired from `std/blocks` brings the blocks it uses, and only those, so the other block names stay free for your own. `niminal presets` lists the catalog, `--kind instrument` or `--kind fx` narrows it, and `niminal presets electric_piano` prints editable source with its helpers. Editor completions offer both an import and a copy of the source.

## std/drums

Twenty-one drums and sound effects, tuned as designed at `c3`. The note transposes the sound; `gain` sets both loudness and strike response. Every preset's `decay` controls the audible tail, including noise-only hats and claps. Hats share a choke group: a closed hat ends an open one.

```nml
use std/drums.{kick_808, snare_tri, hat_closed}
```

| Family | Presets and controls (besides `freq` and `gain`) |
| --- | --- |
| Kicks | `kick_deep`, `kick_808`, `kick_punch`, `kick_click`, `kick_dirty`: `decay`, `punch`, `click`, `drive`. |
| Snares | `snare_tri`, `snare_tight`, `snare_fat`: `decay`, `snap`, `tone`, `drive`. |
| Claps | `clap`, `clap_room`: `decay`, `tone`, `spread` (burst rate). |
| Hats | `hat_closed`, `hat_open`, `hat_tick`: `decay`, `tone`. |
| Tom | `tom`: `decay`, `punch`, `rate`, `drive`. |
| Rim | `rim`: `decay`, `knock`, `rate`, `drive`. |
| Cowbell | `cowbell`: struck inharmonic body and upper modes; `decay`, `tone`, `metal`. |
| Crash | `crash`: six inharmonic square oscillators plus noise; `decay`, `tone`, `metal`. |
| Sound effects | `zap` (`decay`, `drop`, `rate`, `drive`), `blip` (`decay`, `scatter`, `rate`, `drive`), `wobble_bass` (`decay`, `wobble`, `rate`, `drive`), `sweep` (`rise`, `decay`, `tone`). |

For a complete drum-machine voice, call `drum(...)` inside your own instrument. It remains an editable NML function in the language prelude, with oscillator, pitch modulation, filtered noise, separate envelopes, drive, EQ and velocity sensitivity. Presets choose those settings and expose only useful performance controls. Cowbell, crash and sweep have their own patches rather than forcing every sound through that one voice.

## std/fx

Twenty-one effects, taken by name. Effects read `in`; most provide a dry/wet `mix`.

| Family | Effects |
| --- | --- |
| Filters | `filter`: `multimode_filter` with a `response` control that moves from low-pass through band-pass and high-pass to a notch, plus `resonance`, `drive` and an optional beat-synced sweep. `ladder_lowpass`: a transistor-style ladder with the same sweep. `vowel_filter`: A/E/I/O/U formants, optional beat-synced movement. |
| Tone and dynamics | `equalizer`, `compressor` (knee and stereo linking), `overdrive` (4× oversampling), `lofi`, `soft_clip`. |
| Space | `echo` (independent left/right times), `room_reverb`, `studio_reverb`. |
| Modulation | `ensemble` (chorus), `swirl` (phaser), `tremolo`; movement follows the tempo. |
| Ring modulation | `ring_mod`: the sound times a sine (`freq`); `character` sweeps ring, wavefold, diode. |
| Focused performance effects | `stutter`, `frozen`, `slice_shuffle`, `trance_gate`. |
| Performance rack | `glitch`: stutter, rewind, slow-down, scatter, freeze, crush and gate in a fixed chain. |

Start with the focused effects when you only need one operation. `stutter`, `frozen` and `slice_shuffle` pass through while `hold` is zero. Automate `hold` to capture and change the sound. `trance_gate` starts open; automate its `open` control with steps to chop a sustained sound without clicks. The larger `glitch` rack remains available for coordinated changes across several operations. See the [opcode reference](/reference/opcodes/) for the individual glitch algorithms and [effect lanes](/reference/language/patterns/#lanes-for-an-effect) for automation.

```nml
use std/fx.{echo, room_reverb, stutter}
```

## Keyboard colours

The electric piano has a rounded body and a separate struck tine; `bark` responds most on harder notes. Its decay shortens up the keyboard, and `release` controls key damping. FM `index` is a conventional phase index in radians, converted to the oscillator's cycles internally. `contour` changes the lifetime of its brighter attack, while a little modulation remains in the tail.

Try `fm_keys(ratio: 1, index: 3, decay: 700ms)` for bass, `ratio: 1.5, index: 1.6, contour: 0.25, decay: 450ms` for mallets, or `ratio: 3.5, index: 4, contour: 0.8, decay: 3sec` for bells.

## Original starter recordings

Twelve original recordings are embedded in both Stage and the CLI. Import them directly: no exported WAVs, downloads or `.niminal` sample folder are needed. A recording is decoded into memory on first use, then shared between sessions.

```nml
use std/samples.{drums, electric_piano}
tempo 120bpm

clip beat {
  instrument: drums
  notes: grid {
    kick:  x... x... x... x...
    snare: .... x... .... x...
    hat:   x.x. x.x. x.x. x.x.
  }
}
clip keys {
  instrument: electric_piano
  notes: [c4 e4 g4 b4]
  gain: -6db
}
beat.start
keys.start
```

`drums` contains `kick`, `snare`, `clap`, `hat`, `open`, `tom`, `cowbell` and `crash`. Use an individual member with `instrument: drums.kick`. The four pitched recordings are `electric_piano`, `fm_keys`, `struck_string` and `metal_bar`. All are rooted at `c3`; other notes transpose them. Hats share a choke group.

These are ordinary samples, with the usual playback, slicing and stretching capabilities. Importing only `drums` keeps the pitched recording names free for synth presets. To use a recording and synthesizer with the same name, import the module with an alias: `use std/samples as recordings`, then `instrument: recordings::electric_piano`.

### Exporting an editable copy

For your own WAVs, standalone source patches, license and kit file:

```sh
niminal samples --out samples/starter
```

The directory must be new, so an export cannot replace edited recordings. Import the local copy with `use samples/starter/starter as sounds`, then use `instrument: sounds::drums` or `sounds::electric_piano`.

The recordings are dry mono 48 kHz PCM WAVs with trimmed, faded tails. Most peaks are adjusted toward -6 dBFS; the sub-heavy 808 uses -1.94 dBFS. There are no third-party samples. The recordings and source patches use the repository's MIT license. See [Samples](/reference/language/samples/) for playback controls.

## Auditioning and editing the collection

From a repository checkout:

```sh
cargo run -p niminal-lang --example audition -- target/audition
```

Open `target/audition/index.html` for each instrument's default, soft, short and long notes, plus melodic chords. Preview gain targets -20 dBFS RMS over the default note's first half-second, capped by a -6 dBFS peak and 18 dB of boost. That gain is fixed across each preset's variations, preserving velocity differences. `report.csv` contains the original levels and preview gains, and each patch is saved beside its audio. The preview is for comparison; it does not change the preset's output gain.

## Migrating to language 0.4

- Replace the `lowpass`, `highpass`, `bandpass` and `band_cut` effects with `filter`. Its `response` picks the shape: 0 for low-pass, 1/3 band-pass, 2/3 high-pass, 1 notch. `cutoff`, `sweep_beats`, `sweep_depth` and `mix` are unchanged, and `resonance` now runs to 1. Its filter is a state-variable one, so it sounds a little different from the old biquads; for the old sound, use `in.lpf(...)`, `in.hpf(...)`, `in.bpf(...)` or `in.notch(...)` in your own `fx`.
- A function's named results may now share a name with a control. A control called `value` no longer stops `contour` working.

## Migrating to language 0.3

- Remove `use std/filters`; `onepole_lp` and `onepole_hp` are now native and need no import.
- Replace `spectral_pitch(...)` with `spectral_warp(...)`; its arguments and latency are unchanged.
- Replace `std/delays`'s `tape(...)` with `dark_echo(...)`. This is a damped delay recipe, without a tape model.
- Take drums from `std/drums`. The introductory `kick`, `snare` and `hat` patches were removed from `std/instruments`; editable teaching versions remain in `examples/synth_drums.nml`.
- Drum presets now expose musical controls rather than every `drum` parameter. For hats and claps, use `decay` instead of `noise_decay`, and `tone` instead of `noise_freq`. Kicks use `punch` instead of `mod_amount` and `click` instead of `mix`; snares use `snap` instead of `mix`. Use `niminal presets NAME` for each full signature, or copy a patch and call `drum(...)` for the full machine.
- A drum note's `gain` now changes its actual output level as well as its strike. Zero gain is silent. Existing patterns that relied on the old velocity-only behavior will play more softly.
