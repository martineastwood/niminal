Niminal macOS alpha — Getting Started

This experimental build is for Apple Silicon Macs running macOS 13 or newer.
APIs, syntax and project formats may change. Keep backups of work you want to keep.
BUILD.json identifies this download's version, source commit and build OS.

1. Install

Open the dmg and drag the entire Niminal folder onto the Applications shortcut:

  /Applications/Niminal/
    Niminal Stage.app
    bin/niminal
    niminal-vscode.vsix
    Examples/

Rust, Node.js, Homebrew and an installer are not needed.

This alpha is ad-hoc signed and is NOT notarized by Apple. macOS may block the
app and the niminal command on first use. After attempting to open one, use
System Settings > Privacy & Security > Open Anyway to approve it if you trust
this download. Do not disable Gatekeeper globally.

2. Play

Open Niminal Stage.app. The audio engine is inside it and plays through your
default sound card, so there is nothing to start first. Open a .nml file (try
Examples/groove.nml) and press Cmd+Enter to evaluate a block of code, or click a
scene to start it. Cmd+. hushes everything.

3. The niminal command (optional)

To use it from Terminal, run this, and add the same line once to ~/.zprofile to
keep it for future windows:

  export PATH="/Applications/Niminal/bin:$PATH"

Then, for example:

  niminal play Examples/groove.nml      play a file; it plays again when you save it
  niminal render Examples/saw_lead.nml --out saw_lead.wav
  niminal --help                         everything else

4. VS Code / Cursor (optional)

In Stage choose File > Install VS Code Extension... (it also offers this the first
time it opens), then reload the editor. Or choose "Extensions: Install from
VSIX..." in the command palette and select niminal-vscode.vsix.

The code you evaluate in the editor plays through Stage, and its clips and
scenes appear in Stage. If Stage is not open, the extension offers to open it.
Errors, completion and hover come from the niminal command (niminal lsp) and work
without Stage open. If the editor cannot find it, set niminal.path to
/Applications/Niminal/bin/niminal

If you edit a file in both Stage and your editor, Stage reloads it when it has no
edits of its own, and asks before saving over a file that changed.

5. Try an example

Copy Examples into a writable project folder, for example ~/Music/Niminal.
Keep projects and samples outside /Applications/Niminal so replacing the
application folder during an upgrade does not overwrite your work.
groove.nml is a larger live coding example. Some examples demonstrate optional
MIDI/OSC hardware features.

6. Upgrade / uninstall

Close Stage before replacing the Niminal folder with a new download. Update the
VSIX too, then reload the editor. There is no automatic updater.
